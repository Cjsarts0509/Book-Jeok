# FileBrowser 관련 노트

요구사항 #4에서 오픈소스 [FileBrowser](https://github.com/filebrowser/filebrowser)를
기반으로 쓰는 방안을 제안하셨습니다. 검토 결과와 선택을 정리합니다.

## 왜 커스텀으로 구현했나
FileBrowser 는 훌륭한 파일 관리 도구지만, 이번 요구사항과 다음 지점에서 충돌합니다.

1. **관리자의 비밀번호 열람(#3)** — FileBrowser 는 비밀번호를 bcrypt 해시로만
   저장하며 평문 열람 기능이 없습니다. 이 요구를 만족하려면 별도 계층이 필수입니다.
2. **완전 커스텀 브랜딩(#6, #8)** — 북적북적 고유 컬러/폰트/인터랙션과
   PC·모바일 별도 UX(#5)를 픽셀 단위로 맞추려면 커스텀 프런트가 유리합니다.
3. **관리자 통합 대시보드(#3, #7)** — 계정 발급·암호 관리·DB 상태를 한 화면에
   묶으려면 자체 API/화면이 필요합니다.

그래서 **FileBrowser 의 개념(계정별 스코프 격리, 업/다운로드)** 은 그대로 계승하되,
요구사항을 100% 만족하는 경량 커스텀 스택으로 구현했습니다.

## 그래도 FileBrowser 를 쓰고 싶다면
하이브리드도 가능합니다.
- FileBrowser 를 계정별 스코프(`--scope /mnt/bookjeok-data/storage/<user>`)로 띄우고,
  북적북적 백엔드는 **계정 발급·인증·암호 열람·DB 상태**만 담당하는 프록시로 두는 방식.
- 이 경우 로그인 SSO 연동과 UI 임베딩(iframe/리버스프록시) 작업이 추가됩니다.

필요하시면 이 하이브리드 구성으로 전환하는 작업도 도와드릴 수 있습니다.
현재 커스텀 구현이 요구사항 8가지를 더 깔끔하게 충족한다고 판단해 기본값으로 택했습니다.
